## Why this census exists

D1 retired the Daraja **outbound** surface in the repository. It did not retire the
merchant-facing console that configures it. The previous D1 census **hand-listed** the files it
checked and missed `merchant-v2.html` and `sokoni-mpesa.js`; the suite caught them, not the census.
So this census is generated by scanning **every tracked file**, not by listing candidates.

Method: `git grep -I -i "daraja"` over all tracked non-`node_modules` paths, in the working tree
**and** at `HEAD`, cross-checked against a live `gcloud functions list` and 180 days of Cloud
Logging. Counts below are **occurrences**, not matching lines.

### Two callback-registration instructions survived D1

D1's changelog records "callback-registration instructions removed from `payments.html` (x3)".
It removed the **URLs**. It left the **instructions that tell a merchant to register them**:

* line 431 — "In Daraja portal → Lipa Na M-Pesa Online → Validation URL. **Paste SOKONI's callback
  URL below.**" — and there is now nothing below it.
* line 653 — "**Register this URL** in your Safaricom Daraja portal under Lipa Na M-Pesa Online →
  CallbackURL." — and `.pmt-callback-box` above it is now empty, so "this URL" refers to nothing.

Both are still on screen. This is the exact instruction class D1 set out to stop, because publishing
that URL is why sellers registered it in their own Safaricom portals — the registrations that keep
D3 blocked. **D1's removal was incomplete, and the census is what caught it.**

## 4. Classification — `sokoni-mpesa.js` (6 occurrences) — DECISION REQUIRED

Two of the six are **live customer-facing strings**, not comments:

## 5. A live defect the census surfaced

`payments.html:1120` hardcodes `const configured = true` (commit `5ee7e3a`, 2026-07-22). That made
the read below it unconditional:

```js
const cfg = snap.data();               // undefined when the doc does not exist
if (det) det.textContent = (cfg.darajaEnv === 'sandbox' ? … ) + ' · ' + (cfg.darajaShortCode || '');
```

`shopSettings/{uid}` was audited on 2026-07-22 as holding **zero documents**. So `snap.data()` is
`undefined`, `cfg.darajaEnv` throws `TypeError`, and the throw is swallowed by the enclosing
`catch(e) { console.warn(…) }`.

**Consequence:** the four hero statistics — Total Received, Today, Pending, Failed — are populated
*after* that line and are never reached. Every merchant sees `—` in all four. The page has been
silently failing to report money since July, and the cause is a Daraja-shaped read that outlived
Daraja. Removing the Daraja read fixes it; no IntaSend surface is involved.

### The outbound three are safe to delete

Zero production-environment invocations in 180 days. The only six calls were `env:sandbox` from the
founder's own handset. No merchant depends on them. They are, however, **still callable today** —
the deployed `darajaSTKPush` predates `548e15d`, so production is running the fully working
implementation, including the browser-supplied-`amount` behaviour recorded in
[[project_payment_authority]]. The repository is Daraja-free outbound; **production is not.**

### The inbound one is not

`darajaSTKCallback` is receiving live POSTs from Safaricom — `196.201.212.69`, most recently
**2026-09-06**. Sellers' external registrations are live and cannot be revoked from this repository.
Deleting the handler would send those callbacks into the void. D3 stays blocked, now with
measurement rather than inference behind it.

> **Separate finding, not this gate:** those 2026-09-03 and 2026-09-06 callbacks were **rejected** —
> `[darajaSTKCallback] Rejected request from unexpected IP: 196.201.212.69`. That address is inside
> Safaricom's published Daraja callback range. The allowlist is refusing genuine Safaricom traffic.
> Not in scope here, and moot while nothing new is pushed, but it should not be lost.

1. **`payments.html` and `merchant-v2.html`** are clean and fully actionable.

5. **Production deletion of the outbound three** is evidence-backed and safe; **inbound deletion is
   not**, and the evidence is now direct rather than assumed.
