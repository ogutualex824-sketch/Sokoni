# Callable reachability — `run.invoker` gaps

Generated by `node scripts/audit-callable-invokers.js --all` on 2026-07-24.

## Finding

**346 of 1192 HTTP-reachable Cloud Functions are unreachable from the browser.**

Their Cloud Run services are missing the `roles/run.invoker` binding for `allUsers`,
so requests are rejected at the invocation layer with **HTTP 403** before the
function code runs. All 346 report state `ACTIVE` — they are deployed and
healthy; they simply cannot be called.

Verified, not inferred: 8 were probed directly and every one returned 403
(addSupplier, adminGetAllDisputes, approveLegalProvider, bookLegalConsultation,
cancelEvent, createCourse, checkInTicket, compareVehicles). The working callables
(createCheckoutSession, bookAppointment, bootstrapDevice) hold `allUsers` and return
401 — the healthy "reached the function, its own auth rejected it" response.

No structural difference explains the split: runtime, `ingressSettings` (`ALLOW_ALL`),
codebase and service account are identical across passing and failing functions.
This is IAM-state drift from deploy history.

## Scope of this finding — read before acting

This is ONE failure mode: a missing invoker binding. It says nothing about whether a
function's own authorization is correct, whether App Check is enforced, whether
Firestore Rules behave, or whether business logic works. Clearing every entry below
means "no endpoint exhibits this specific IAM misconfiguration" — NOT "all callables
are correctly configured".

Some entries may be **intentionally private** (admin or server-to-server, invoked with
an IAM identity rather than from a browser). Confirm those and record them as
deliberate rather than granting `allUsers`. Many others are plainly user-facing and
are genuine defects — e.g. `bookLegalConsultation`, `createCourse`, `checkInTicket`,
`compareVehicles`, `createEvent`.

— the camelCase form silently targets nothing:
