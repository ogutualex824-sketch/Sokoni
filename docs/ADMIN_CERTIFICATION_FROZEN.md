## Reusable rule — `min-width: auto`

**Any newly introduced flex or grid child in the admin workspace should be given
`min-width: 0` unless its intrinsic minimum is deliberately required.**

`min-width: auto` is the CSS **default** on flex and grid items. It sets the automatic
minimum to *min-content*, which **silently overrides a declared width**. One mechanism
accounted for **six** apparently unrelated responsive defects across four sections:

| Page | Symptom | Reality |
|---|---|---|
| `settlement-dashboard` | 632px block overflowing a 1fr track at 1024 | grid item could not shrink |
| `commission-admin` | `.main` measured 402px inside a 390px shell | flex item could not shrink |
| `trust-safety` (sidebar) | declared `220px`, **rendered 390px** — full viewport | min-content beat the declared width |
| `trust-safety` (stats) | 181px overflow | `minmax(140px,1fr)` made 140px a hard floor |
| `commission-engine` | 5px overflow, **no element wider than the viewport** | the SUM of a row that refused to compress |
| `search-quality` | `header.topbar` floored at 442px | flex children could not shrink |

These surfaced only **after** the shared shell reserved a 244px sidebar column — it removed
the slack that had been hiding them. A latent defect that becomes visible when layout gets
tighter is still a defect; the shell exposed them rather than causing them.

Related idiom: wide content (tables, tab strips, carousels) must **scroll inside its own
container**, never widen the page. The shell exposes `.sk-adm-scroll` for this.

## Architectural lessons worth keeping

**A rule in a "responsive" stylesheet is not necessarily responsive-scoped.** Two separate
defects came from rules sitting *outside every media query* in `sokoni-responsive.css` and
applying at desktop.

**A broad selector plus a shorthand property is how one rule silently reaches unrelated
surfaces.** `overscroll-behavior: contain` on `[class*="hscroll"]` was wrong for two
interaction models in *opposite* directions — it blocked vertical page scrolling on
carousels, and pointlessly contained the horizontal axis on chat lists.

**Per-page enumeration does not hold.** `sokoni-nav-engine.js` carried a hand-maintained
`_SKIP` list naming seven admin pages, which is exactly why some consoles were clean and
others silently inherited customer navigation. Registry membership now answers it for all 50.

**Four consumer injectors reached into the admin workspace** — consent banner, consumer
header, bottom nav, splash — each through a different mechanism, each now answered by
`data-sokoni-workspace="admin"` derived from registry membership.

**Signed-out and insufficient-authority are different failure modes.** A destination can look
safe and still be wrong for the state that produced it. Three branch/destination mismatches
survived the denial invariant because it judged destinations, not branches.

## Method notes — errors caught before they became conclusions

Recorded because the value of this evidence depends on how it was checked.

- **Four automated classifiers failed** before the admin surface census converged; AMBIGUOUS
  became a first-class outcome rather than a bucket quietly emptied.
- **The auth-architecture predictor missed in both directions** — `monitor.html` predicted
  BLOCKED, certified 7/7; `executive-dashboard` and `messages-admin` predicted NORMAL, both
  BLOCKED. Useful for slicing work; unreliable as a verdict. **Runtime is the verdict.**
- **Probes reported the wrong document** more than once — measuring a login page after a
  redirect, or reading "nothing rendered" as "nothing exposed". Each was caught by a control.
- **An exit code was read as a result** when the harness had been piped through `grep`.
- **A concurrent run produced stale results** for three pages edited mid-run; discarded and
  re-run rather than reported.
- **A dead local server produced 0/35** — an infrastructure failure, not a UI regression.
- **A flaky drawer check** on `reliability-center` was recorded as flaky with two independent
  controls (the changed selectors do not exist on that page; it reproduces cleanly otherwise),
  not as "the rerun passed".
- **15 admin taps appeared to fail** and were all explained by `#adminLock` covering the page
  — the documented BLOCKED state, with `admin-os` passing as the control.
