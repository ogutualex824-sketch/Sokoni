### 🔴 REAL APPLICATION FAILURE — found and fixed

**`seller-delivery.html` threw `Can't find variable: firebase` on its first statement.**

`firebase.js` is loaded as `<script type="module">` (line 159) and is therefore deferred.
The page's bootstrap is a **classic inline script** (line 162) that runs at parse time and
called `firebase.auth()` at line 177 — before `firebase.js:508` assigns `window.firebase`.

The IIFE died immediately, so `_initTabs()` never ran and **none of the six Firestore
listeners** (riders, active, pending, history, failed, packageRequests) ever attached.

This affected **Delivery Hub `#deliveries` (primary tier)** and **Riders `#riders`**.

The same defect had already been found and repaired in `dispatch.html` and `driver.html` —
both carry comments describing it. `seller-delivery.html` was missed. Fixed with the same
`_whenFirebaseReady()` pattern. **Verified green by the gate** (24 failures → 22, REAL → 0).

### 🟡 UNPROVEN ×8 — needs an authenticated run

These are **not** "probably fine". The harness has no Firebase session, so every embedded
destination sees an unauthenticated browser:

| Destination | Finding |
|---|---|
| `products` (via `inventory`) | deep-switch never confirms — the seller iframe renders the **login page** (measured: `document.title` = `"Log In to SOKONI"`). Whether an authenticated approved seller reaches Products is unsettled. |
| `minishop` | iframe stays `about:blank` — dynamic src resolves at click time, an unauthenticated uid owns no shop, so `showMiniShopEmpty()` is the honest state. The assertion does not model it. |
| `verification` | `permission-denied` on directory load. Consistent with no session; a rules hole would look identical from here. |
| `pos-setup` | `PAGEERROR: cancelled`. No rule matched — defaults to UNPROVEN rather than being assumed environmental. |

**The gate has never tested an authenticated merchant.** That is the single largest
remaining hole, and it is why `GATE 31/31` must not be read as "all destinations proven".
`scripts/test-merchant-sell-authenticated.js` already establishes the pattern — the Auth
emulator attached at the network boundary via Playwright, shipped SDK unmodified.

### 🟢 ENV ×14 — mechanism measured

`Origin http://127.0.0.1:PORT is not allowed by Access-Control-Allow-Origin` on
`deliveries, messages, kra-tax, disputes, reports, shop, devices`. App Check cannot attest
an ephemeral loopback origin, and that origin is not among Firebase's authorized domains.
Measured directly: `content-firebaseappcheck.googleapis.com/…:exchangeDebugToken → 403`.

**Nothing is suppressed.** The classifier is additive reporting over the same totals; an
unrecognised failure defaults to UNPROVEN, never ENV.
