# Commission — the browser's rate table quotes what the server resolves

**Branch:** `commission-snapshot/lane-parity` (from main line `bd2a513`) · **NOT landed** · **Hosting NOT deployed**
**Related:** [[COMMISSION-money-chain-ladder-tests]] · `functions/commission-config.js` (the one rate authority, unchanged)

## The defect (source, not production)

`sokoni-commission-rates.js` is the browser's copy of the commission rates, generated by
`scripts/build-commission-snapshot.js`. When the 2026-09-13 packages renamed the plans, the plan table was
regenerated with the new keys (`free`, `professional`, `business`, `enterprise`). The generator's
**hand-written** lookup in its template still mapped to the retired `seller_*` keys and fell back to
`'seller_free'`, and none of those keys exists any more.

`marketplacePct()` therefore returned **`undefined` for 11 of 15 spellings**: every `seller_*` id, `basic`, `pro`,
`starter`, `growth`, unknown, empty and null. `build-commission-snapshot.js --check` still said "in sync", because
it compared text generated by the same stale template.

- **Display-only.** The callers are the merchant rates table in `merchant-v2.html` and the Free/Basic/Pro/Enterprise
  label in `hub-register.js` and `onboarding-seller.html`. None sends the value anywhere; the server calculates every
  commission.
- **Not live.** Hosting serves an older rates file (marketplace 3%, no lane API). That is a separate
  **Hosting-release** decision, outside this repair.

## The repair (source/build only)

**1. The generator** takes the plan-name table from the **server**:
- `MARKETPLACE_TIER_ALIASES` is read from the real config source. It is not exported, and this repair changes no
  server code, so the generator compiles `commission-config.js` in a private module with one appended line that hands
  the constant out. The file itself is never modified.
- Every entry is cross-checked against the exported `resolveMarketplaceRate`. A renamed constant or a disagreeing
  entry **throws**; the generator never emits a guess.
- The default plan is the server's `MARKETPLACE_DEFAULT_PLAN`.
- The browser's `marketplacePct()` now mirrors `resolveMarketplaceRate()` exactly and never returns `undefined`. A new
  `marketplacePlan()` returns `{plan, matched}`, as the server does.

**2. The build guard checks answers, not only text.** `--check` now evaluates the committed file as a page would.
It asks it, for every canonical plan, every server alias, a genuinely unknown plan and empty input, what the server
says, and fails on any disagreement. This is a **source/build certification control**; it deploys nothing.

**3. `sokoni-commission-rates.js` regenerated.** The authoritative 15% marketplace rate, the 5% POS rate and the
KES 10 minimum are unchanged.

**4. `scripts/test-commission-browser-parity.js` (new)** compares browser and server answers, with no rate literal.
It keeps the three fallback classes **separate**:

| class | example | both sides |
|---|---|---|
| known canonical plan | `business` | recognised, its own rate |
| genuinely unknown plan | `platinum`, `seller_gold` | unrecognised → the server's default plan = the **highest** rate |
| empty / absent / non-string | `''`, `null`, `undefined`, `0`, `123` | exactly what the server resolves (default plan, unrecognised) |

**5. `test-marketplace-plan-ladder.js`: the 12 stale assertions corrected**, with expectations derived from the
authority:

| assertion | now |
|---|---|
| A0 (new) | the flat shape |
| A1 | derived rate |
| A2 | canonical plan names |
| A3 | the general floor invariant: only a genuine 0% escapes the minimum |
| A4 | a sale derived to sit below the authorised rate's crossover, so the KES 10 minimum is really exercised |
| B1 | the server's default plan at the highest rate |
| G1 | rebuilt: the resolved plan follows the fixture. It still catches the broken-fixture class it caught historically |
| G1b | the rate moves exactly as the authority says |
| H5 → H5a/b/c | the three fallback classes |

## Separate, not in this repair

- **The deployed older rates file.** Production serves marketplace 3% with no lane API. This is a Hosting-release
  decision.
- **Optional server hygiene.** Exporting `MARKETPLACE_TIER_ALIASES` read-only from `commission-config.js` would let the
  generator import it rather than compile it out of the source. That is a server-file change, so it was not made.
- **Server edge case, executed and not changed.** `resolveMarketplaceRate('constructor')` and `('__proto__')`
  **throw** (`Cannot read properties of undefined (reading 'rateFraction')`). The alias table is read with plain
  property access, so an Object-prototype name resolves to a non-plan. `toString` and `hasOwnProperty` resolve safely.
  The browser uses own-property checks and resolves all four to the default plan. Plan ids come from server-stored
  subscriptions, so exposure is low. The fix is a one-line own-property check in server code, left for a separate,
  authorised server change. The parity suite deliberately does not probe these names, because the server throws there.
- **Payment-destination, STK and UI failures** stay separate workstreams.
