## A correction to the earlier finding

The first report of this gap said a browser "could write session documents directly" and that
deploying would leave the database "open on session documents". **That was wrong.**

The live ruleset contains **650 explicit match blocks and no catch-all** — verified on both
trees with a pattern that finds recursive wildcards where they exist. Firestore therefore
**default-denies** `connectSessions` on the live lineage.

The correct reading: absent rules cause **denial, not exposure**. The real consequence is
functional — a participant could not read their own session and a peer could not read a signal
addressed to them, so incoming calls would silently never appear. It remained a hard deployment
blocker; it was not a security hole.

## The contract, unchanged from the certified source

| Collection | read | write |
|---|---|---|
| `connectSessions/{id}` | admin, or a uid already in `resource.data.participants` | **`if false`** |
| `connectSessions/{id}/signals/{id}` | only `resource.data.to` — not even the sender | **`if false`** |
| `connectVerifications/{id}` | admin or the subject | **`if false`** |
| `connectVideoGrants/{id}` | admin, or the owner/member named | **`if false`** |

`write: if false` is the whole security argument, and it is stronger than a field-level
allowlist: **there is no writable field to guard.** A browser cannot create a session, cannot add
itself to one, and cannot alter an authority-controlled field, because it cannot write at all.

Reads are matched against `resource.data` — the **server's** participant list decides, never a
list the requester supplies.

## Live rules preserved — proven structurally, not by inspection

```
hunks      1
deletions  0
additions  42
common prefix 255,818 chars   common suffix 4 chars   inserted 2,407 chars
prefix + suffix accounts for ALL of the live file: YES
```

The live ruleset is a strict prefix+suffix of the ported one. Nothing was removed or altered.
Top-level match blocks 650 → 653.

Each collection was checked for a pre-existing block first and the port **refuses** rather than
adds a second: a duplicate match block **ORs**, and `write: if false` is void the moment another
block allows the write.

## The emulator executed the real artifact

`firestore.rules.build` was regenerated by `scripts/build-firestore-rules.js` (the `.build` file
is generated; editing it directly would be erased) and the suite loads that text itself through
`initializeTestEnvironment` — the emulator's own rules discovery does not work in this repository,
because `firebase.json` declares `firestore` as an array.

**37 passed, 0 failed**, covering every required category: unauthenticated denied, stranger
denied, sender-cannot-read-own-signal, client-created session denied, admin-write denied,
legitimate participant read allowed.

**Counter-proof: 33 passed, 4 failed** against a ruleset without the Connect blocks. A suite that
cannot fail proves nothing; this one fails when the rules are absent, so its passes mean
something. It is also demonstrably not a deny-everything ruleset — four assertions require reads
to **succeed**.

## Indexes — derived from queries, not copied

| Query | Index |
|---|---|
| `connectListIncoming`: `where calleeUid ==`, `where status in [...]` | `connectSessions [calleeUid, status]` |
| the signals listener: `where to ==`, `orderBy createdAt` | `signals [to, createdAt]` |

408 → 410. The pre-existing 408 are asserted byte-identical **and in their original order**; the
append cannot move an existing entry.

### Recorded, not invented

`connectExpireStaleSessions` queries `where('status','==',from)` + `where('createdAt','<',cutoff)`.
That shape normally needs its own composite index, and **neither lineage declares one**. It is a
pre-existing condition of the certified source, not something this port introduced, and an index
nobody asked for is not added here. Worth resolving before that scheduled function is relied on.

## What this does not cover

Deployment of these artefacts is a separate, gated operation with its own lineage history, which
this port does not touch. The rule stands: **no Functions deployment while the Connect rules are
not deployed**, and no Hosting deployment exposing the Connect UI without the server and database
contract behind it. The release moves as one unit — UI, Functions, Rules, Indexes.
