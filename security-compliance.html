Enterprise Compliance Posture — Grade A−

Security 6.0 delivers financial-grade Zero Trust for SOKONI's marketplace, SmartPOS, payments, logistics, and AI services. All core controls are implemented and verified. Three items remain for A+ certification.

Access Control & Identity
AuthenticationPass
Multi-factor authentication with TOTP, WebAuthn/Passkeys, and risk-based step-up challenges.
  • Firebase Auth + custom claims for role management
  • TOTP MFA (RFC 6238) — `securityMFA` collection
  • WebAuthn / FIDO2 Passkeys — `securityPasskeys` collection
  • Trusted device registry — trust scores 0–100
  • Adaptive auth: step-up on high-value actions
  • Remember-me with device binding
Access ControlPass
Attribute-Based Access Control (ABAC) via `evaluateAccessRequest` CF — role + device + session + risk + amount.
  • 7-level role hierarchy: guest → super_admin
  • Firestore rules: owner-only, branch-isolated, CF-write-only
  • No wildcard grants — every collection explicit
  • Firestore v2 default-deny on unmatched paths
  • Admin privileges enforced via Firebase custom claims only
Session ManagementPass
Enterprise session lifecycle: creation, rotation, anomaly detection, and remote revocation.
  • Server-side session records — `securitySessions` collection
  • Session rotation to prevent fixation attacks
  • Impossible travel detection (IP geo-anomaly)
  • Remote logout — terminateAllSessions CF
  • Device-level session revocation
  • Scheduled cleanup of expired sessions (24h)
Data Protection & Privacy
Data in TransitPass
All data encrypted in transit via Firebase's enforced TLS 1.2+ infrastructure.
  • HSTS: max-age=63072000; includeSubDomains; preload
  • Firebase Hosting enforces HTTPS — no HTTP fallback
  • Redis TLS (when REDIS_URL configured)
  • Cloud Functions HTTPS-only endpoints
Data at RestPass
Google Cloud managed encryption at rest for Firestore, Storage, and Cloud Functions environment.
  • Firestore: AES-256 encryption at rest (GCP managed)
  • Firebase Storage: AES-256 at rest
  • eTIMS credentials: AES-256-GCM application-layer encryption
  • Secrets stored in GCP Secret Manager (16 secrets)
  • No plaintext credentials in codebase
Data RetentionPartial
Retention policies defined; automated enforcement partially implemented.
  • Firestore PITR enabled (point-in-time recovery)
  • Sessions auto-expire after 7 days inactivity
  • Audit logs: immutable, no deletion by normal admins
  • Formal data retention schedule: document pending
  • Automated PII deletion workflow: planned
Payment Security (PCI-DSS Alignment)
Transaction SecurityPass
HMAC-signed transactions, idempotency keys, server-side verification — no client-side payment confirmation trusted.
  • PAYMENT_HMAC_SECRET via GCP Secret Manager
  • crypto.timingSafeEqual on all HMAC comparisons
  • Idempotency keys on all payment mutations
  • Replay attack prevention via nonce tracking
  • Velocity checks: 5 STK pushes per user per minute
  • Transaction signing on all order creation
Fraud PreventionPass
SASOS fraud engine with 25+ weighted signals and 4 risk tiers (0–30 allow, 31–60 monitor, 61–80 challenge, 81–100 block).
  • Payment velocity checks
  • Impossible travel on payment events
  • Merchant risk scoring
  • Customer risk scoring
  • Automatic review queue for suspicious txns
  • AI-assisted pattern recognition (Claude Haiku)
Zero Trust CheckoutPass
Every checkout evaluated by ABAC engine before payment is processed. Step-up auth on high-value transactions.
  • SokoniZeroTrust.guard() called in placeOrder()
  • Device trust score included in payment context
  • Transaction amount in access decision context
  • Step-up modal for transactions ≥ KES 100,000
  • All payment events written to securityAuditLog

Audit Trail
Immutable Audit SystemPass
SHA-256 hash chain audit log. Every security event, payment, admin action, and configuration change is recorded. Audit entries cannot be deleted by normal administrators — only Super Admin with dual approval.
  • securityAuditLog collection: tamper-evident hash chain
  • Events: Authentication, Payments, Refunds, Inventory, Pricing, Role changes, Admin actions, Security events, Config changes
  • Each entry: previousHash + SHA-256(content + previousHash) = currentHash
  • Chain integrity verifiable by getAuditLogIntegrity CF
  • CF-write-only: Firestore rules prevent direct client writes
  • Retention: indefinite (no TTL on audit collection)
